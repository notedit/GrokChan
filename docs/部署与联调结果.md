### 一键重部署

```bash
scripts/deploy.sh          # 读取 /home/box/secrets/grokchan.env，用 --var 传变量、--secrets-file 传密钥
```

`wrangler.toml` 没有被改动（`PUBLIC_ORIGIN` 仍是占位符），生产变量和 secrets 全部在部署时传入。
`GC_ENV_FILE=/path/to/other.env scripts/deploy.sh` 可换配置文件。需要 Node ≥ 22（脚本自动加入 PATH）和 `CLOUDFLARE_API_TOKEN`。

### 签发/重签设备 token

```bash
set -a; . /home/box/secrets/grokchan.env; set +a
curl -s -X POST -H "X-Passcode: $SITE_PASSCODE" "$GC_ORIGIN/api/devices/stackchan-01/token"   # 明文只返回一次，重签会使旧 token 失效
```

## 线上联调

脚本：`bridge/scripts/online-smoke.mjs`（`node bridge/scripts/online-smoke.mjs`，Node ≥ 22）。用模拟 Stack-chan 连线上环境。
**注意**：语音回合那一步会真的向用户的 grokbot webhook 发一条测试消息（“GrokChan integration test, please ignore this message.”），不要反复运行。

结果 27/27 通过（延迟为从北京所在网络到 Cloudflare 的单次测量，仅供参考）：

| 项 | 结果 | 延迟 |
|---|---|---|
| `/api/health` | configured / stackchan / mcp_auth 均为 true | 164 ms |
| 设备错 token / 无 token | 握手后以 close 4003 拒绝 | 225 / 273 ms |
| WS 连接（TLS+Upgrade） | 成功 | 311 ms |
| `session.hello` | 成功，`voice.uplink` = pcm_s16le/16k/mono，max 15000 ms / 480000 B | 121 ms |
| MCP 无 key / 错 key | 401 | ~190 ms |
| MCP `initialize`、`tools/list`（11 个工具） | 通过 | 105 / 74 ms |
| `list_devices`、`get_device_status(fresh)` | 通过 | 157 / 209 ms |

## 未验证 / 局限

- 真机行为（Wi-Fi、I2S 麦/扬、舵机、屏幕、VAD、增益）全部未验证，联调用的是模拟设备。
- 模拟设备的上行速度约 2.5 倍实时；真机按 1 倍实时发送，partial 延迟会相应变长。
- 只测了一次真实 grokbot 往返；grokbot 回复内容和耗时取决于主 bot 的例程。
- `GC_TLS_INSECURE=1`（不校验服务器证书）未在 workers.dev 真机上验证。
- ElevenLabs 密钥仍是聊天里贴过的那把，按用户决定上线时再轮换：轮换后改 `grokchan.env` 里的 `ELEVENLABS_API_KEY`，再 `scripts/deploy.sh`。

## 固件

`firmware/include/gc_config.h`（已被 gitignore，含设备 token，**不要提交、不要外传**）已填好服务器域名、`GC_DEVICE_ID=stackchan-01`、`GC_DEVICE_TOKEN`；`GC_WIFI_SSID` / `GC_WIFI_PASS` 留空，需要你填。`GC_VOICE_ENABLED` 仍为 0。

```bash
cd firmware
$EDITOR include/gc_config.h                  # 填 Wi-Fi
export PATH=/home/box/.venvs/pio/bin:$PATH   # box 上的 pio；本机用自己的 pio 即可
pio run -e cores3                            # 产物：.pio/build/cores3/firmware.bin
pio run -e cores3 -t upload                  # USB 连接 CoreS3 后烧录
pio device monitor                           # 串口日志，115200
```

box 上预编译的 `.pio/build/cores3/firmware.bin` 是在 Wi-Fi 为空时编译的，只能验证编译；填完 Wi-Fi 后需重新编译。要在本机烧录，先用 CopyFromBox 把整个 `firmware/` 目录（含 `gc_config.h`）拿到本机再编译。

## Grok Bot 挂载 MCP

在 Grok Bot 的 MCP / 自定义连接器里添加（Streamable HTTP，无状态，无 SSE）：

```json
{
  "mcpServers": {
    "grokchan": {
      "url": "https://grokchan-bridge.leeoxiang.workers.dev/mcp",
      "headers": { "Authorization": "Bearer <MCP_API_KEY：见 /home/box/secrets/grokchan.env>" }
    }
  }
}
```

可用工具：`list_devices`、`get_device_status`、`move_head`、`reset_pose`、`set_expression`、`show_text`、`set_led`、`speak`、`stop_audio`、`set_volume`、`emergency_stop`。多数工具带 `device_id`（本机为 `stackchan-01`）。
验证：不带 `Authorization` 应返回 401；带正确 key 的 `tools/list` 应返回 11 个工具。
